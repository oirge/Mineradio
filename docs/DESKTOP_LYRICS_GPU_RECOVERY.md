# 桌面歌词与 GPU 恢复修复（2026-10-25）

基线：`oirge/Mineradio` 的 `ba5dd1b`（v2.5.3）。工作分支为 `fix/desktop-lyrics-gpu-recovery`。用户于 2026-10-25 授权修复后发布新版，本轮目标为 v2.5.4，发布记录以 `RELEASE.md` 为准。

## 已复现的问题

- 歌词窗口大量区域透明，旧代码以外框露出 160×96 像素判断可达。文字中心完全移出屏幕、仅透明边角仍可见的位置会被保存并在重启后恢复。旧版失败测试为 3 失败、1 通过。
- 解锁拖动直接移动原生窗口，保存阶段才校正坐标，实际窗口不会同步回到安全位置。
- 意外隐藏、最小化、失去置顶或持续无响应没有恢复入口；恢复额度用完后长期不补充。
- 快速切换可见状态时未取消旧 RAF，可能产生多条绘制链并增加 CPU 开销。
- GPU 失败计数没有时间窗，正常退出/外部结束也会累计；软件档没有受控重试途径。

历史故障存档已经被用户清除，以上为实际重现的代码缺陷，不把它们宣称为两次历史故障唯一根因。本次只读检查到的本机歌词位置 `289,-159,1382,410` 尚有可达文字，不应强制删除该偏好。

## 修复边界

- 歌词可达判断检查文字中心是否位于实际显示器内；保留合法半出屏位置，允许横向/纵向相邻双屏慢拖，以及不同尺寸显示器的接缝。
- 拖动先校正真实窗口，再持久化相同位置。重启时自动纠正旧的不可见坐标。
- 原生可见性异常延迟 120ms 合并恢复，不抢焦点；无响应先等待 5 秒再有限重载；连续健康 60 秒后恢复三次重载预算。关闭/旧实例/退出及旧加载回调不能复活窗口。
- RAF 和闲置 timer 各只有一个所有者；隐藏取消、恢复合并。原帧率、250ms 闲置间隔及视觉样式不变。
- GPU 仅累计十分钟内的故障，忽略正常退出/外部终止。软件档冷却后试运行兼容硬件模式，先持久化回退标记，再配置 Chromium；写盘失败不试探，第二实例不写状态。
- 两分钟无故障且硬件合成实际启用后保存兼容档；失败回软件档，冷却跨版本保留。首次冷却 24 小时，失败后每次冷却 7 天；冷却到期后的下次启动自动试探，每次启动至多一次，没有终身次数上限。成功后清空连续尝试次数。缺少时间戳的旧软件档允许首次探测。未强制独显、未绕过驱动黑名单。
- 用户明确要求「所有型号的 GPU 加速异常之后会自动恢复」。恢复路径不读取显卡厂商或型号，统一以 Chromium 的硬件合成状态确认，适用于 NVIDIA、AMD、Intel 等设备。测试机器的 RTX 4060 只代表实测硬件，不能表述为已实测所有型号；驱动仍不支持硬件加速时保留软件回退，并继续按冷却重试。Electron 加速配置只在启动前生效，因此该恢复在下次启动应用时进行，不会在播放中为了探测而定时重启。
