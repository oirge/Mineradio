# 启动速度优化

## Windows 原生启动测量

手动运行 `Verify`，选择 `browser_suite=startup`，会额外触发 Windows 原生启动测量。任务核对 v2.7.9 和 v2.8.0 安装包 SHA256 后解包原版播放器，不运行安装程序。两个版本交替执行，每版每种场景测 6 次：全新空档案，以及已建索引的 5,000 首合成曲库（有效 WAV、专辑封面和逐曲 LRC）。输出在 `native-startup-evidence` 工件中。

记录进程启动到原生窗口可见、首个内容帧和首页初始化，以及观察到曲库队列就绪的时间。空曲库另测导入 WAV 到播放，大曲库另测点击播放到媒体时间实际推进。使用隔离的非主档案，不代表主档案迁移、清空系统磁盘缓存后的冷启动或物理扬声器发声延迟。此测量应在托管 Windows runner 执行，不在本机打开播放器。

首次通过的 Windows 对照中，v2.7.9 → v2.8.0 的空曲库首页就绪中位数为 1,241 → 1,132 ms，含 5,000 首的已建索引曲库首页就绪为 879 → 771 ms，观察到队列就绪为 1,540 → 1,445 ms。v2.8.1 移除本地服务重复端口绑定；另做 20 组独立 Node 进程的绑定专项对照，成功绑定中位数为 28.6 → 26.6 ms，仅测该步骤、不代表整机启动。正式构建可用 `compare_startup=true` 直接比较待发布的 Windows 程序与 v2.8.0。

## 全部主播放器启动入口

- 共用宿主只在打开热键弹窗时创建弹窗，减少重复的设置和首页渲染。封面占位直接使用同色像素，歌单架随主场景首次绘制初始化。设置玻璃只计算有折射的边缘，13 种尺寸的 RGBA 输出与上一轮逐字节一致。
- Folia 从 HTML 解析阶段预载本地播放器入口和两个大依赖。保存为唱片墙、海报墙或电台墙时，只提前准备该视图，墙面在播放器激活时直接显示。保存为影厅时，歌词控件与影厅资源并行启动，影厅着色器预编译使用实际尺寸的渲染目标。

使用上一轮已验收的本地版本作基线。同机无头 Chromium（SwiftShader）、环回地址、空曲库和独立浏览器上下文，基线和候选交替运行。Mineradio 记录首次内容绘制与首页初始化都完成的时间，Folia 记录宿主握手与对应页面控件都就绪的时间，影厅另等到真实 3D 首帧。Windows 安装版的启动耗时仍待实测。

简洁和普通歌词页为最后一次去重首页渲染后的 10 组对照，其余入口来自前一轮各 8 组对照。简洁模式有 9 组缩短。普通歌词页相对上一轮的端到端变化仍在样本波动内，关键入口模块的请求中位数从子页导航后的 414 ms 提前至 215 ms。与已发布的 `v2.7.9` 重新做 8 组同场对照时，普通歌词页从 804.4 ms 降至 666.3 ms，8 组中有 7 组缩短。三种墙面从播放器激活到墙面控件就绪的额外等待中位数由 182–300 ms 降至低于 1 ms。原始数据见 `verification/player-startup-all/`。

最终代码通过 1776 项 Node 回归和 133 项 Folia 单测，以及 Folia 类型和产物校验。隔离浏览器中的启动与 WAV 实播、主界面与 Folia 中英文、玻璃像素与交互、唱片墙和海报墙共享播放引擎均通过。

## Folia 图标分包

## Folia 首屏（对比 `cfc12f2a`）

- 记住 Folia 时，HTML 解析到容器就开始加载 iframe，宿主接管同一个 iframe；子页等宿主就绪后才挂载并发出请求。默认打开 Mineradio 时不请求 Folia 资源。
- 曲库、视觉设置、播放设置和工具按需加载；嵌入版直接初始化宿主选择的中文或英文，不再加载独立应用的语言检测和印尼语资源。
- 记住 Folia 时，原版保留交互画布但不创建隐藏的 WebGL 渲染器。首次切回原版才在同一画布初始化；之后切换复用渲染器。音频、曲库和队列仍由宿主持有。

### 默认进入 Folia 复测

- 原版首页先完成 DOM 初始化和曲库恢复的首帧调度，再启动主场景 WebGL。着色器随实际绘制编译，省去整棵场景的预编译。Folia 显示时暂停宿主搜索和播放栏的 SVG 贴图刷新，返回原版时按现有尺寸补刷。
- 默认 Folia 首屏按需加载几何背景。嵌入构建保留中英文播放器与视觉设置文案，并裁掉独立应用的命令面板、版本记录和 Ponder 字典。
- 本地服务用异步文件操作清理过期安装包缓存。下载前仍等清理完成再继续，保留当前安装包、待安装新版本和续传文件。

## v2.7.3 基线（历史）

基于最新版 `oirge/Mineradio` 主分支 `e445493f`，保持首页、Folia、SVG 玻璃质感、画质与唯一宿主音频不变。

### 改动与证据

- 曲库恢复的顶层入口原来排队等待 700ms，DOMContentLoaded 的 420ms 请求被单次调度门禁忽略。现在只从 DOMContentLoaded 调度，避免尾部脚本尚未加载就开始恢复；等首个 RAF 后用零延时任务开始，没有 RAF 的隐藏窗口由 120ms 定时器兜底。显式传入 delay 的调用仍保留原行为，帧与定时器竞争只会恢复一次。
- 主进程启动只快照上次迁移留下的目录，递归删除改为后台异步任务。设置恢复、迁移、权限初始化及页面导航顺序保持原样；清理不重新扫描，因此不会删除本次迁移新建的目录。清理失败不阻止启动。

| 局部场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 生产恢复调度函数，虚拟时钟首个 RAF 在 16ms | 700ms 开始读库 | 16ms 开始读库 |
| 本机 Node 文件系统样本，2000 个旧迁移文件，启动同步阻塞 | 189.2ms | 4.5ms |

这些数字分别是固定调度等待和旧迁移目录存在时的阻塞时间，不是整机从双击到出声的启动时长。磁盘、GPU、曲库大小及是否记住 Folia 都会影响实际表现。

### 验证

本地及 Windows 云端 Node 回归均为 1761 项通过、1 项可选基准跳过、0 失败。恢复单次执行、隐藏窗口兜底、显式延迟、恢复失败和清理所有权均有生产函数行为测试。`fb416ae1` 的完整 Verify `43403091608`、原生窗口布局 `43403091609` 和视频导出 `43403091764` 全部成功。启动专项的默认／记住 Folia 两场景共 10 项检查通过，覆盖尾脚本延迟 300ms、真实 WAV 起播、暂停继续和音频对象不被替换；结果保存为 `artifacts/ui-language/startup-report.json`。

最终提交 `17286c6b` 的完整 Verify `43544233780`（15m16s）、原生布局 `43544233597` 与实际视频导出／解码 `43544233517` 全部成功。启动专项 10 项、工具专项 7 项及完整播放、翻译、9 样本布局、双语／恢复与全部视觉套件通过。此前验收脚本的自动收起与长按释放时序失败及修正过程保留在 docs/PROJECT_MEMORY.md，未放宽超时、断言或画质。用户明确要求发布后，v2.7.4 于北京时间 2026-11-14 10:51:28 正式公开并设 Latest，构建、四资产及公开更新清单核验通过，完整发布事实与摘要见 RELEASE.md 顶部。
